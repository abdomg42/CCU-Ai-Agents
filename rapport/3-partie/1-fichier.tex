\section{Implémentation du pipeline}

\subsection{Construction du graphe}
La classe \texttt{DiagnosticPipeline} dans \texttt{orchestrator/pipeline.py} construit le graphe LangGraph en déclarant les nœuds et les arêtes. Le nœud \texttt{collectors} encapsule le parallélisme des trois agents collecteurs.

\begin{lstlisting}[language=Python, caption={Construction du graphe LangGraph}, label={lst:pipeline}]
from langgraph.graph import StateGraph, START, END

class DiagnosticPipeline:
    def __init__(self) -> None:
        self.graph = self._build_graph()

    def _build_graph(self) -> StateGraph:
        builder = StateGraph(GraphState)
        builder.add_node("intake", run_intake)
        builder.add_node("collectors", _collect)
        builder.add_node("root_cause", run_root_cause)
        builder.add_node("ticket_manager", run_ticket_manager)
        builder.add_node("remediation_explainer", run_remediation_explanation)
        builder.add_node("content_guardrail", run_content_guardrail)
        builder.add_node("report_generator", run_report_generator)
        builder.add_node("notifier", run_notifier)

        builder.add_edge(START, "intake")
        builder.add_edge("intake", "collectors")
        builder.add_edge("collectors", "root_cause")
        builder.add_edge("root_cause", "ticket_manager")
        builder.add_edge("ticket_manager", "remediation_explainer")
        builder.add_edge("remediation_explainer", "content_guardrail")
        builder.add_edge("content_guardrail", "report_generator")
        builder.add_edge("report_generator", "notifier")
        builder.add_edge("notifier", END)
        return builder.compile()
\end{lstlisting}

\subsection{Parallélisme des collecteurs}
La fonction \texttt{\_collect} tente d'abord une exécution asynchrone via \texttt{asyncio.gather}. Si une boucle d'événements est déjà active, elle bascule vers un \texttt{ThreadPoolExecutor}.

\begin{lstlisting}[language=Python, caption={Parallélisme des collecteurs}, label={lst:collectors}]
async def _collect_async(state: GraphState) -> dict[str, Any]:
    results = await asyncio.gather(
        asyncio.to_thread(run_logs, state),
        asyncio.to_thread(run_context, state),
        asyncio.to_thread(run_rag, state),
    )
    merged: dict[str, Any] = {}
    for r in results:
        merged.update(r)
    return merged
\end{lstlisting}

\subsection{Root cause reasoner}
L'agent de raisonnement implémente une logique déterministe qui s'appuie sur les sources collectées. Si un ticket similaire fournit une cause racine, celle-ci est retenue. Sinon, l'agent applique des règles par type d'incident. En l'absence de source suffisante, il retourne une cause \texttt{indéterminée}.

\begin{lstlisting}[language=Python, caption={Refus d'hallucination dans le root cause reasoner}, label={lst:rootcause}]
def _deterministic_cause(self, state: GraphState) -> RootCauseSchema:
    sources, _ = self._collect_sources(state)

        return RootCauseSchema(
            confidence="faible",
            cause="indeterminee",
            explanation="Aucune source suffisante ...",
            source_ids=[],

    # Correlation avec le ticket similaire le plus proche

\subsection{Requête GraphRAG}
La requête Cypher suivante illustre la combinaison de la recherche vectorielle native Neo4j avec un filtre de proximité de graphe.

\begin{lstlisting}[language=SQL, caption={Recherche GraphRAG dans Neo4j}, label={lst:cypher}]
CALL db.index.vector.queryNodes($index_name, $candidate_limit, $query_embedding)
YIELD node AS t, score
WHERE score >= $threshold
  AND (size(product_names) = 0 OR EXISTS {
    MATCH (t)-[:RELATED_TO_PRODUCT]->(p:Product)
    WHERE p.name IN product_names
  })
RETURN t.id AS ticket_id, t.summary AS summary,
       t.root_cause AS root_cause, t.resolution AS resolution, score
ORDER BY score DESC
LIMIT $top_k
\end{lstlisting}

\section{Sécurité et guardrails}

\subsection{Principe de non-exécution automatique}
Le projet respecte une règle fondamentale : \textbf{aucune action technique n'est jamais exécutée automatiquement} sur un système réel. L'agent produit des diagnostics, des explications et des rapports, mais toute action corrective reste sous le contrôle d'un opérateur humain.

\subsection{Guardrail de contenu}
Le guardrail de contenu filtre les informations personnelles identifiables (PII) avant toute génération de rapport ou notification. Il s'appuie sur une logique de whitelist pour les actions autorisées et refuse toute action hors périmètre.

\subsection{Refus d'hallucination}
Le \texttt{root\_cause\_reasoner} retourne systématiquement une cause \texttt{indéterminée} avec une confiance faible lorsqu'il ne peut citer aucune source. Cette mesure limite les diagnostics inventés par le modèle.
